## 1. Настроенные цели

В разделе «Цели» настроен тип «Целевое событие · ex JS-событие», условие
«Совпадает» с точным идентификатором:

| Название | Идентификатор | Что фиксируется |
|---|---|---|
| Нажатие на телефон | `contact_phone` | Клик по ссылке tel:, не состоявшийся звонок |
| Написать на почту | `contact_email` | Клик по mailto:, не отправленное письмо |
| Написать в Telegram | `contact_telegram` | Переход к ludno_info |
| Написать в Max | `contact_max` | Переход в Max |
| Открыть проектный материал | `material_download` | Клик по ссылке на PDF/CAD/BIM/архив/таблицу сайта или admin.ludno.ru; не подтверждение завершённого скачивания |
| Перейти в соцсети | `social_click` | Telegram-канал или Pinterest |
| Успешно подписаться на рассылку | `newsletter_subscribed` | Успешный ответ сервера формы подписки |

Последняя цель относится к подписке, а не к запросу коммерческого предложения.

`contact_telegram` — 662397781; `contact_max` — 662397805;
`material_download` — 662397910; `social_click` — 662398014;

В события не передаются введённые имя и почта, текст письма или параметры ссылки.
Автоцели счётчика могут существовать параллельно: не складывайте их достижения
с соответствующими ручными целями как независимые обращения.

## 2. По каким запросам находят сайт

Открыть «Отчёты → Источники → Поисковые запросы».
Выбрать период, например последние 90 дней, и источник «Яндекс».
Сохранить отдельно брендовый сегмент (Людно/ludno) и сегмент без этих слов.
Добавить доступные показатели визитов, посетителей и конверсии по выбранной цели.

Это поисковые фразы переходов, а не все запросы, по которым сайт показывался.
Метрика скрывает часть фраз при низкой посещаемости и некоторых комбинациях
группировок/сегментов. По документации в отчёте показываются запросы, по которым
перешло более 10 пользователей за выбранный период. Поисковик также может не
передавать фразу. Добавление страницы входа или цели не гарантирует, что фраза
останется видимой в детализации.

Для показов, позиций и кликов используйте также Яндекс Вебмастер и Google Search
Console. В Search Console анализируйте запросы с фильтром по странице. Не пытайтесь
связывать каждую скрытую поисковую фразу с конкретным посетителем или заявкой.

## 3. Какие страницы приводят обращения

В отчёте «Страницы входа» выделить визиты из поисковых систем.
Смотреть страницу входа, визиты и конверсию по одной выбранной контактной цели.
Это подходящий отчёт для оценки посадочных страниц, с которых началось посещение.
Подписку, скачивание и контактные клики анализировать отдельно.

## 4. Какие разделы читают

С каждым просмотром передаётся параметр `page`:

- `section`: раздел карты сайта, например «Игровое и спортивное оборудование»;
- `group`: группа, например «Безопасность» или «Проектирование»;
- `type`: посадочная, раздел сайта, карточка оборудования, статья и т. п.;
- `path`: адрес страницы без параметров запроса.

Открыть «Параметры визитов» и раскрыть `page → section` или `page → group`.
Посещения разных разделов в одном визите могут попасть в несколько групп:
суммировать эти группы как уникальные визиты нельзя. Параметры посещённых страниц
не заменяют встроенную «Страницу входа» и не определяют источник привлечения.
Для числа просмотров конкретных URL используйте отчёты содержания по страницам.
В целях дополнительно передаётся контекст страницы, на которой произошёл клик.

Для первого дашборда сохранить четыре отчёта:

1. Поисковые системы: визиты и конверсии по контактной цели.
2. Поисковые запросы: брендовые и небрендовые переходы отдельно.
3. Страницы входа из поиска: визиты и выбранная конверсия.
4. Параметры визитов: посещаемые разделы и группы.

## 5. Проверка после публикации

На ludno.ru использовать отладку Метрики (`?_ym_debug=2`), проверить один просмотр
при открытии и просмотры при внутренних переходах. Проверить контактную ссылку,
социальный канал и ссылку на собственный файл; ссылка на нормативный PDF стороннего
сайта не должна считаться проектным скачиванием. Подписку проверять только своим
тестовым адресом: успешное событие возникает после реального ответа сервера.

Пользовательские события и ручные просмотры отключены на localhost и других
доменах. Вебвизор и передача персональных данных этим изменением не включаются.
